# 小伴同学 — PRD（产品需求文档）

> AI 情绪陪伴故事伙伴 Web MVP
> 版本：v0.1（MVP）　|　作者：产品经理管培生应聘作品　|　日期：2026-09

---

## 一、产品定位

### 1.1 一句话定位
"小伴同学"是一个让 3-6 岁孩子用自然对话表达情绪、用专属故事获得陪伴的 AI 伙伴；让家长在 5 分钟内看懂孩子今天的心情。

### 1.2 产品形态
- **当前阶段**：Web App MVP，验证核心交互、情绪价值、家长付费意愿。
- **未来形态**：毛绒玩具 / 故事机 / 智能音箱（"软件定义玩具"）。
- **商业假设**：家长愿意为"情绪可见 + 亲子沟通脚手架"持续付费（硬件 + 订阅）。

### 1.3 为什么先做 Web MVP
1. 硬件周期长、模具 + 安规 + BOM 成本高，先验证交互逻辑再投入。
2. 浏览器 Web Speech API + localStorage 可零成本跑通核心流程。
3. 可直接挂 GitHub Pages 给面试官/家长试用，传播成本低。
4. 数据全本地，规避儿童数据合规风险，便于早期测试。

## 二、用户画像

### 2.1 核心用户：3-6 岁儿童（"朵朵"代表）

| 维度 | 描述 |
| --- | --- |
| 认知 | 语言表达 3-5 字短句为主，能命名简单情绪（开心/生气/害怕），抽象情绪（委屈/孤独）尚需成人帮命名 |
| 动机 | 想被看见、被回应；睡前有强烈的"被陪伴"需求 |
| 痛点 | 情绪来了说不清楚；大人总在"教育"而不是"听" |
| 使用习惯 | 不会打字、依赖语音；注意力短，单次 5-15 分钟 |
| 安全 | 易受惊吓、易模仿危险行为，需内容兜底 |

### 2.2 决策用户：家长（"朵朵妈"代表）

| 维度 | 描述 |
| --- | --- |
| 画像 | 25-40 岁，一二线城市，双职工，本科以上，对孩子的情绪健康有焦虑 |
| 动机 | "想知道孩子今天过得怎么样"、"希望孩子有人陪聊" |
| 痛点 | 下班到家孩子已困，无时间深度沟通；不知道怎么开口问情绪；老人带娃只报喜不报忧 |
| 决策权 | 愿意为"情绪可见 + 亲子沟通"付费，单次客单 ¥100-300 可接受 |
| 关注 | 安全（数据/内容）、不让孩子上瘾、不替代真实陪伴 |

### 2.3 反画像（不是我们的用户）
- 想用 AI 教识字、教英语的家长（教育型玩具赛道，非情绪陪伴）。
- 追求炫技硬件（大屏/投影/AI 视觉）的极客家长。

## 三、使用场景

### 3.1 主场景：睡前 5-15 分钟
- **触发**：孩子上床，灯光调暗，家长把手机/平板放在枕边。
- **流程**：选一个今晚的伙伴 → 按住说今天发生的事 → 伙伴共情回应 → 孩子点开专属故事听一遍 → 入睡。
- **结束**：时长锁到点温柔结束，不让孩子赖着不睡。

### 3.2 次场景：情绪爆发当下
- **触发**：孩子哭闹、生气、害怕。
- **流程**：家长引导孩子跟伙伴说说怎么了 → 伙伴先共情"听起来你有点难过" → 帮孩子命名情绪 → 给一个温暖小故事。
- **家长侧**：当下不评判，事后看仪表盘了解情绪关键词 + 建议话题，晚饭/周末再聊。

### 3.3 家长侧场景：碎片时间查看
- **触发**：通勤、午休、孩子睡着后。
- **流程**：打开家长仪表盘 → 30 秒看完今日情绪关键词 + 安全记录 → 抄 3 条建议话题。
- **价值**：不抢孩子的睡前时间，却能"看见"孩子的情绪。

## 五、功能优先级

### P0（MVP 必做，已实现）

| 功能 | 价值 | 验证假设 |
| --- | --- | --- |
| 角色选择（3 个固定人格） | 让孩子有"我的伙伴"感 | 人格一致性提升黏性 |
| 按住说话 + 文字兜底 | 3-6 岁可独立操作 | 语音是核心输入 |
| Mock AI 短句回应（≤3 句） | 不说教，先共情 | 共情比教育更打动家长 |
| 关键词情绪识别 | 给家长"情绪可见" | 家长愿意为可见付费 |
| 专属故事（孩子是主角） | 情绪被接纳 + 睡前仪式感 | 故事是付费转化的钩子 |
| 家长仪表盘 | 决策用户的核心价值 | 家长看后是否改变沟通方式 |
| 时长锁 | 不让孩子上瘾 | 缓解家长焦虑 |
| 安全兜底 | 儿童产品的底线 | 必须做 |
| 种子数据 | 打开即可演示 | 传播链路顺畅 |

### P1（下一版）

| 功能 | 说明 |
| --- | --- |
| 真实 LLM 接入（已留接口） | 更自然的对话，需家长自填 Key |
| 多孩子档案 | 二胎家庭 |
| 情绪周/月趋势 | 长期情绪健康追踪 |
| 故事库 + 收藏 | 孩子愿意反复听的故事 |
| 家长话题社区 | "今晚大家都问什么" |

### P2（量产硬件）

| 功能 | 说明 |
| --- | --- |
| 毛绒外壳 + 喇叭 + 麦克风 | "软件定义玩具"硬件化 |
| 离线本地推理 | 网络断连可用 + 隐私本地化 |
| 情绪多模态（语调 + 表情） | 摄像头/麦克风分析情绪强度 |
| 亲子双向留言 | 家长可对孩子"留言"，孩子可听 |

### 不做（明确排除）

- 管理后台（MVP 用写死配置）。
- 复杂账号体系（MVP 用 localStorage 隔离）。
- 付费集成（MVP 只做成本估算展示）。
- 真实硬件协议（仅留概念）。

## 六、MVP 范围（验收）

1. 能跑通完整流程：选角色 → 说话 → AI 回应 → 情绪识别 → 生成故事 → 家长报告。
2. 移动端可正常使用（响应式 + 触控大按钮）。
3. AI 失败时有 Mock 兜底，演示不崩。
4. 有安全过滤（4 类敏感词 + 引导话术）。
5. 有种子数据，打开就能演示。
6. 可部署 GitHub Pages。
7. 同时产出 PRD / 竞品 / 调研 / 计划 / 测试 / 复盘。

## 七、非功能需求

| 维度 | 要求 |
| --- | --- |
| 性能 | AI 回复时延 Mock ≤300ms，真实 LLM ≤8s 超时回落 |
| 安全 | 敏感词黑名单 + 引导话术 + 安全记录 + 家长可删 |
| 隐私 | 不收集真实姓名/学校/地址/电话；数据仅本地 |
| 可用性 | 3-6 岁可独立完成主流程，文字密度低 |
| 兼容 | Chrome/Edge/Safari 主流浏览器，移动端优先 |
| 可演示 | 打开即有种子数据，无需配置 |

## 八、成功指标（MVP 阶段）

| 指标 | 目标 | 说明 |
| --- | --- | --- |
| 完整流程完成率 | ≥70% | 首次访问用户跑通选角色→故事 |
| 平均会话时长 | 5-10 分钟 | 不过长，符合睡前场景 |
| 家长仪表盘打开率 | ≥50% | 至少看一次仪表盘 |
| 安全兜底触发后引导完成率 | 100% | 命中后必有引导话术 |
| Mock 演示成功率 | ≥95% | 离线/无 Key 也能演示 |
| 真实 LLM 回落率 | ≤10% | 网络正常时不应频繁回落 |
| 单轮成本估算 | ≤¥0.01 | gpt-4o-mini 量级 |

## 九、风险与缓解

| 风险 | 等级 | 缓解 |
| --- | --- | --- |
| ASR 在儿童发音下准确率低 | 高 | 文字兜底 + Mock 演示路径 |
| 真实 LLM 出不安全内容 | 高 | 系统提示词 + 安全检查双层 + Mock 回落 |
| 家长担忧数据隐私 | 中 | 全本地存储 + 不收集真实信息明示 |
| 孩子上瘾 | 中 | 时长锁 10/15 分钟 + 到点温柔结束 |
| 替代真实陪伴 | 中 | 故事结尾引导"告诉爸爸妈妈今天的心情" |
| 3-6 岁不会操作 | 中 | 大按钮、低文字密度、角色头像明显 |

---

## 十、迭代路线（3 个月）

- **M1**：Web MVP（本版）— 验证核心交互 + 招聘作品集。
- **M2**：真实 LLM 接入 + 情绪周趋势 + 故事库（10 个骨架）。
- **M3**：硬件 PoC（树莓派 + 毛绒外壳）+ 离线小模型 + 内测 10 户家庭。

## 十一、术语表

| 术语 | 说明 |
| --- | --- |
| ASR | Automatic Speech Recognition，浏览器语音识别 |
| TTS | Text-to-Speech，语音合成朗读 |
| Mock | 不调真实 LLM 的规则式回复，用于离线演示 |
| 时长锁 | 家长设定单次使用分钟数，到点结束 |
| 专属故事 | 把孩子昵称 + 当天情绪事件编入的小故事 |
| 情绪关键词 | 开心/生气/害怕/委屈/平静 五类 |
